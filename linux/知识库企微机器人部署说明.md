# 知识库企微机器人部署说明

第二套 OpenClaw Gateway：只接一只新的企业微信机器人，用工作区里的 Markdown 回答问题。不接 OA，不接 Redis，不加入 `xa-shared`。

现网 IT 服务台仍占宿主端口 `18789`、容器名 `xa-gateway`。本套使用另一目录、另一容器、另一只机器人、宿主端口 `18790`。容器内监听端口保持 `18789`。同一套 BotId / BotSecret 只能由一个 Gateway 持有。

2026-10-22 在虚拟机 `adtek-Virtual-Machine` 上已验收：镜像 `ghcr.io/openclaw/openclaw:2026.9.2`，插件 `@wecom/wecom-openclaw-plugin@2026.7.2`，`/healthz` 为 `{"ok":true,"status":"live"}`，`config validate` 通过，`WeCom default` 已启用，路由 `wecom / default → kbagent`，WebSocket 认证成功。日志中的模型为 `bailian/qwen3.8-flash`。

Windows 目录 `F:\workspace\xa-kb` 里的 `config/openclaw.json` 和工作区六文件仍是第一次启动用的初稿，没有企微通道。不要用这份初稿覆盖虚拟机上已经跑起来的 `config/openclaw.json`。

企微通道细节以 [WeCom 通道插件接入手册.md](WeCom%20通道插件接入手册.md) 为准。本文件只写这套知识库实例。

## 1. 实例对照

| 项 | 已有 IT 服务台 | 本套知识库 |
| --- | --- | --- |
| 目录 | 已有那套目录 | 含 `docker-compose.yml` 的 `xa-kb` |
| 容器名 | `xa-gateway` | `xa-kb-gateway` |
| 宿主端口 | `127.0.0.1:18789` | `127.0.0.1:18790` |
| 容器内端口 | `18789` | `18789` |
| Agent | `itservicedeskagent` | `kbagent` |
| 插件 | OA 桥接 + 企微 | 只装企微 `2026.7.2` |
| 机器人 | 已有 Bot | 必须是另一只 Bot |

`18790` 是本机控制台和健康检查端口。企微走网关出网的 WebSocket（`wss://openws.work.weixin.qq.com`），不要把 `18790` 对公网开放。若 `18790` 也被占用，只改宿主侧为 `18791`：compose 的 `ports`、`controlUi.allowedOrigins` 里的 `18790`、以及 `curl` / SSH 隧道。`entrypoint.sh` 的 `--port 18789` 和 json 里的 `gateway.port` 保持 `18789`。

所有命令都在 `xa-kb` 目录执行。凭据路径写 `./secrets/`。这台虚拟机的目录不在 `/home/adtek/xa-kb`。

镜像保持 `2026.9.2`。日志里的 `openclaw update`（`v2026.10.5`）不要执行。

## 3. entrypoint.sh

容器内端口固定 `18789`。

```sh
#!/bin/sh
set -eu
for secret in \
  gateway_token \
  wecom_bot_id \
  wecom_bot_secret \
  model_api_key \
  model_base_url \
  model_id \
  model_ref
do
  path="/run/secrets/$secret"
  if [ ! -s "$path" ]; then
    echo "missing or empty secret: $path" >&2
    exit 1
  fi
done

export OPENCLAW_GATEWAY_TOKEN="$(tr -d '\n' < /run/secrets/gateway_token)"
export OPENCLAW_STATE_DIR="/home/node/.openclaw"

export XA_DOMESTIC_API_KEY="$(tr -d '\n' < /run/secrets/model_api_key)"
export XA_DOMESTIC_BASE_URL="$(tr -d '\n' < /run/secrets/model_base_url)"
export XA_DOMESTIC_MODEL_ID="$(tr -d '\n' < /run/secrets/model_id)"
export XA_DOMESTIC_MODEL_REF="$(tr -d '\n' < /run/secrets/model_ref)"

export XA_IT_WECOM_BOT_ID="$(tr -d '\n' < /run/secrets/wecom_bot_id)"
export XA_IT_WECOM_BOT_SECRET="$(tr -d '\n' < /run/secrets/wecom_bot_secret)"

exec node dist/index.js gateway --bind lan --port 18789
```

### 5.2 写入白名单后再安装插件

只写 `plugins.allow`。先不要 `enabled: true`，先不要 `channels.wecom`。

```bash
docker exec -it xa-kb-gateway node dist/index.js config set \
  plugins.allow '["wecom-openclaw-plugin"]'

docker compose down && docker compose up -d
sleep 8
curl -sS http://127.0.0.1:18790/healthz

docker exec -it xa-kb-gateway node dist/index.js plugins install @wecom/wecom-openclaw-plugin@2026.7.2
docker exec -it xa-kb-gateway node dist/index.js plugins list
```

`plugins list` 里应有 `@wecom/wecom-openclaw-plugin`，版本 `2026.7.2`，状态 enabled。Gateway `2026.9.2` 自己点名的就是这个版本。裸包名不带版本会走 catalog；本环境 catalog 目标就是 `2026.7.2`。

若已经把 `enabled` 设为 `true` 且重启后 `/healthz` 失败、日志只有 `plugin not installed`：把 enabled 改回 `false`，保留 `plugins.allow`，拉起后再安装。

```bash
python3 - <<'PY'
import json
p = "config/openclaw.json"
with open(p) as f:
    cfg = json.load(f)
cfg["plugins"]["entries"]["wecom-openclaw-plugin"]["enabled"] = False
with open(p, "w") as f:
    json.dump(cfg, f, indent=2, ensure_ascii=False)
    f.write("\n")
print("allow =", cfg["plugins"].get("allow"))
PY
sudo chown 1000:1000 config/openclaw.json
docker compose down && docker compose up -d
sleep 8
curl -sS http://127.0.0.1:18790/healthz
```

### 5.3 插件已启用后再写通道

`${...}` 两侧的单引号必须保留。

```bash
docker exec -it xa-kb-gateway node dist/index.js config set \
  plugins.entries.wecom-openclaw-plugin.enabled true
docker exec -it xa-kb-gateway node dist/index.js config set \
  plugins.entries.wecom-openclaw-plugin.hooks.allowConversationAccess true

docker exec -it xa-kb-gateway node dist/index.js config set channels.wecom.enabled true
docker exec -it xa-kb-gateway node dist/index.js config set channels.wecom.botId '${XA_IT_WECOM_BOT_ID}'
docker exec -it xa-kb-gateway node dist/index.js config set channels.wecom.secret '${XA_IT_WECOM_BOT_SECRET}'
docker exec -it xa-kb-gateway node dist/index.js config set channels.wecom.dmPolicy open
docker exec -it xa-kb-gateway node dist/index.js config set channels.wecom.groupPolicy open
docker exec -it xa-kb-gateway node dist/index.js config set channels.wecom.allowFrom '["*"]'
docker exec -it xa-kb-gateway node dist/index.js config set channels.wecom.sendThinkingMessage false

docker exec -it xa-kb-gateway node dist/index.js config set bindings '[
  {"type":"route","agentId":"kbagent","match":{"channel":"wecom","accountId":"default"}}
]'

docker compose down && docker compose up -d
sleep 8
curl -sS http://127.0.0.1:18790/healthz
docker exec -it xa-kb-gateway node dist/index.js channels list
docker exec -it xa-kb-gateway node dist/index.js agents list --bindings
docker logs --tail 80 xa-kb-gateway
```

成功标准：

| 检查 | 期望 |
| --- | --- |
| `channels list` | `WeCom default: installed, configured, enabled` |
| `agents list --bindings` | `kbagent`，路由 `wecom accountId=default` |
| 日志 | `WebSocket connected` 之后 `Authentication successful` |
| `config validate` | `Config valid`（命令须带第 2 节的 `-e`） |

`agents list` 不带 `-e` 时，模型会显示成字面量 `${XA_DOMESTIC_MODEL_REF}`。以网关日志里的 `bailian/qwen3.8-flash` 为准。

## 7. 知识文档

新会话会注入且只注入这 6 个文件名：`AGENTS.md`、`SOUL.md`、`IDENTITY.md`、`USER.md`、`HEARTBEAT.md`、`MEMORY.md`。同目录其它 `*.md` 不会自动进入提问。`skipBootstrap: true` 只禁止自动生成空模板，已有的这 6 个文件仍会注入。单文件上限 `80000` 字符，合计上限 `200000`。两处 `bootstrapMaxChars` 都要写，只写 defaults 对已绑定的 `kbagent` 不生效。

执行会这批资料约 38 个文件、13.6 万字符，生产计划部单部门已超过 8 万字符，不能整包贴进 `AGENTS.md`。每条问题根据 `AGENTS.md` 里的文件名索引调用 `read` 读取相关文件。`tools.fs.workspaceOnly` 为 `true`，只能读工作区。

文件必须放在虚拟机 `xa-kb/workspace/` 根目录，和 `AGENTS.md` 同一层。Windows 上的 `F:\workspace\xa-kb\asd\` 不在容器里。

初稿会导致企微没有文字回复，不要继续使用：

- `AGENTS.md` 写「只依据 MEMORY.md」且「不要调用任何工具」
- `MEMORY.md` 是空索引，并禁止 `read`
- `HEARTBEAT.md` 写「无待办则保持静默」

在 `xa-kb` 目录执行，生成索引并换掉这 6 个文件：

```bash
python3 - <<'PY'
from pathlib import Path
ws = Path("workspace")
skip = {"AGENTS.md", "SOUL.md", "IDENTITY.md", "USER.md", "HEARTBEAT.md", "MEMORY.md"}
docs = sorted(p for p in ws.glob("*.md") if p.name not in skip)
if not docs:
    raise SystemExit("workspace 根目录没有其它 .md")
lines = [
    "# 规则",
    "",
    "你是企业微信资料问答机器人。员工每发一条问题，都必须用中文给出文字回复，禁止沉默。",
    "",
    "回答前先根据下面的文件名索引，调用 read 读取相关的知识文件，可以读多份。只用读到的正文作答。资料里没有的，回复「资料里没有」。",
    "",
    "不要 read 本文件、SOUL.md、IDENTITY.md、USER.md、HEARTBEAT.md、MEMORY.md。不要 write，不要 edit，不要建单。",
    "",
    "## 知识文件索引",
    "",
]
for p in docs:
    lines.append(f"- {p.name}")
(ws / "AGENTS.md").write_text("\n".join(lines) + "\n", encoding="utf-8")
(ws / "SOUL.md").write_text("# 工作原则\n\n先 read 索引里的知识文件，再简短回答。每条提问都要有文字回复。\n", encoding="utf-8")
(ws / "IDENTITY.md").write_text("# 身份\n\n名称：文档助手。根据工作区知识文件回答问题。\n", encoding="utf-8")
(ws / "USER.md").write_text("# USER\n\n同时服务多名员工。不要建立个人档案，不要把姓名或部门写进本文件。\n", encoding="utf-8")
(ws / "HEARTBEAT.md").write_text("# HEARTBEAT\n\n心跳不要主动发消息。员工提问不受本文件限制，必须按 AGENTS.md 回复。\n", encoding="utf-8")
(ws / "MEMORY.md").write_text("# MEMORY\n\n会议资料在同目录的其它 Markdown 文件中。回答前按 AGENTS.md 的索引 read，不要把正文写入本文件。\n", encoding="utf-8")
print(f"indexed {len(docs)} files")
PY
sudo chown -R 1000:1000 workspace
docker compose restart
```

`indexed` 后面应是知识文件份数。之后每新增或改名一个 `*.md`，再跑一遍该脚本。

在企微里单独发一条 `/new`，再单独发一条 `/context detail`。`AGENTS.md` 应在 Project Context 中且没有 `TRUNCATED`，`Skills list` 为 0。旧会话会继续用改文件之前的规则。然后再问一个只有某份纪要里才有的数字。

## 8. 开启「思考中」

这是企微客户端的占位，配置项为 `channels.wecom.sendThinkingMessage`。消息进网关后约 1～2 秒出现「思考中」，正文仍要等模型 `read` 完再替换这条占位。它不打开百炼思考链。模型侧保持 `thinkingDefault: off` 和 `compat.thinkingFormat: "qwen"`。

插件必须 ≥ `2026.7.2`。本套已安装的就是 `2026.7.2`。低于该版本时占位会停在 `finish=false`，正文发不出去。

```bash
docker exec -it xa-kb-gateway node dist/index.js plugins list
docker exec -it xa-kb-gateway node dist/index.js config set channels.wecom.sendThinkingMessage true
docker compose restart
sleep 8
curl -sS http://127.0.0.1:18790/healthz
```

私聊发一句「你是谁」，不要连发。另开终端：

```bash
docker logs -f --timestamps xa-kb-gateway
```

| 现象 | 日志 |
| --- | --- |
| 占位已发出 | `onReplyStart` 且 `isShowThink=true` |
| 正文已发出并关掉占位 | `kind=final` → `Reply message sent` → `finish=true` |
| 占位关不掉 | 只有 `finish=false`，没有对应的 `finish=true` |

占位不消失或后续消息都没有回复时，立刻关回并重启：

```bash
docker exec -it xa-kb-gateway node dist/index.js config set channels.wecom.sendThinkingMessage false
docker compose restart
```

## 10. 排障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `curl 18790` 连接被重置，日志只有 `plugin not installed` | `enabled: true` 早于安装 | 第 5.2 节把 enabled 改回 `false`，健康后再 `plugins install @wecom/wecom-openclaw-plugin@2026.7.2` |
| `config validate` 报 7 条 missing env，且 zsh 找不到 `/home/adtek/xa-kb/secrets` | 用了错误的家目录路径 | 在 `xa-kb` 目录改用 `./secrets/`，见第 2 节 |
| `plugins list` 刷 missing env | 这次 `docker exec` 没带 `-e` | 忽略。看网关日志里的模型名和 `Authentication successful` |
| 企微完全没有文字 | `HEARTBEAT.md` 要求静默，或规则禁止工具且 `MEMORY.md` 是空的 | 按第 7 节重写 6 个文件，再 `/new` |
| 知识文件放进 workspace 仍答「资料里没有」或答非所问 | 其它 `*.md` 不会注入；`group:fs` 禁止 `read` | 第 6 节放开 `read`，第 7 节生成索引 |
| 有「思考中」或日志有 inbound，但始终没有正文 | `timeoutSeconds` 仍是 20 | 改为 `120` 并 `docker compose restart` |
| 「思考中」一直转 | 插件低于 `2026.7.2`，或该会话流没 `finish=true` | 第 8 节改回 `false` 并重启 |
| 两个机器人抢同一条连接、重复回复 | 两套 Gateway 用了同一 Bot | 本套换新的 BotId / BotSecret，另一套不要同时持有 |
