# 知识库企微机器人部署说明

第二套 Gateway：一只新的企微机器人，按工作区里的 Markdown 回答问题。不接 OA，不连 MySQL。通用做法同 IT 服务台（[安装手册](OpenClaw%20Gateway%20Linux%20服务器安装手册.md)、[企微手册](WeCom%20通道插件接入手册.md)），本文只写差异。

2026-10-22 已在 `adtek-Virtual-Machine` 验收：镜像 `ghcr.io/openclaw/openclaw:2026.9.2`，插件 `@wecom/wecom-openclaw-plugin@2026.7.2`，模型 `bailian/qwen3.8-flash`，路由 `wecom/default → kbagent`。

## 1. 与 IT 服务台的差异

| 项 | IT 服务台 | 知识库 |
| --- | --- | --- |
| 目录 / 容器 | `~/xa` / `xa-gateway` | `xa-kb` / `xa-kb-gateway` |
| 宿主端口 | `127.0.0.1:18789` | `127.0.0.1:18790`（容器内仍 `18789`） |
| 镜像 | 自建 `xa-gateway-oa` | 官方 `ghcr.io/openclaw/openclaw:2026.9.2` |
| Agent | `itservicedeskagent` | `kbagent` |
| 插件 | OA 桥接 + 企微 | 只有企微 |
| 工具 | 只 `oa_workflow`，禁 `read` | 只 `read`（`fs.workspaceOnly: true`），禁 `write` / `edit` |
| `bootstrapMaxChars` / `bootstrapTotalMaxChars` | 40000 / 默认 | 80000 / 200000（两处都写） |
| 模型超时 | 20 秒 | 120 秒（要读多份纪要，20 秒会表现为不回复） |
| secrets | 12 个 | 7 个（去掉 OA 与身份转换的 5 个） |
| 机器人 | 原 Bot | 必须另一只 Bot |

18790 被占就只改宿主侧（compose `ports`、`allowedOrigins`、curl / SSH 隧道），容器内端口和 `gateway.port` 不变。镜像保持 2026.9.2，日志提示的 `openclaw update` 不要执行。

## 2. 目录、secrets、entrypoint、compose

所有命令在 `xa-kb` 目录执行，secret 路径写 `./secrets/`（这台虚机的目录不在 `/home/adtek/xa-kb`）。

```text
xa-kb/
├── docker-compose.yml
├── entrypoint.sh
├── config/openclaw.json
├── workspace/        AGENTS.md 等 6 个规则文件 + 知识 *.md（同一层）
├── extensions/
└── secrets/          700；文件 600；属主 1000:1000
```

secrets（变量名与 IT 服务台相同）：`gateway_token`、`wecom_bot_id`、`wecom_bot_secret`、`model_api_key`、`model_base_url`、`model_id`（`qwen3.8-flash`）、`model_ref`（`bailian/qwen3.8-flash`），各 `.txt` 一行、`printf '%s'` 写入。

`entrypoint.sh`：

```sh
#!/bin/sh
set -eu
for s in gateway_token wecom_bot_id wecom_bot_secret model_api_key model_base_url model_id model_ref; do
  [ -s "/run/secrets/$s" ] || { echo "missing or empty secret: /run/secrets/$s" >&2; exit 1; }
done
r() { tr -d '\n' < "/run/secrets/$1"; }
export OPENCLAW_GATEWAY_TOKEN="$(r gateway_token)" OPENCLAW_STATE_DIR=/home/node/.openclaw
export XA_IT_WECOM_BOT_ID="$(r wecom_bot_id)" XA_IT_WECOM_BOT_SECRET="$(r wecom_bot_secret)"
export XA_DOMESTIC_API_KEY="$(r model_api_key)" XA_DOMESTIC_BASE_URL="$(r model_base_url)"
export XA_DOMESTIC_MODEL_ID="$(r model_id)" XA_DOMESTIC_MODEL_REF="$(r model_ref)"
exec node dist/index.js gateway --bind lan --port 18789
```

`docker-compose.yml`：以仓库 `docker/docker-compose.yml` 为底，改这几处：

- `image: ghcr.io/openclaw/openclaw:2026.9.2`
- `container_name: xa-kb-gateway`
- `ports: ["127.0.0.1:18790:18789"]`
- `secrets` 只留上面 7 个（服务下和底部两处）
- 删掉 `oa-bridge-config.json` 那条 volume

`chmod 755 entrypoint.sh && sudo chown -R 1000:1000 .`

## 4. 启动顺序

插件没装上之前不能有 `channels`、`bindings`，`plugins.entries.wecom-openclaw-plugin.enabled` 也不能是 `true`，否则 `unknown channel id` 或 `plugin not installed`，`curl 18790` 被重置。

1. 先写一份去掉 `channels`、`bindings`、`plugins.entries` 的配置，只保留 `plugins.allow`：

   ```bash
   python3 - <<'EOF'
   import json
   p = "config/openclaw.json"
   c = json.load(open(p))
   c.pop("channels", None); c.pop("bindings", None); c["plugins"].pop("entries", None)
   json.dump(c, open(p, "w"), ensure_ascii=False, indent=2)
   EOF
   docker compose up -d && sleep 8 && curl -sS http://127.0.0.1:18790/healthz
   ```

   日志应有 `gateway ready`、`agent model: bailian/qwen3.8-flash`。刚 up 就 curl 可能被重置，等几秒再查。

2. 装插件：

   ```bash
   docker exec -it xa-kb-gateway node dist/index.js plugins install @wecom/wecom-openclaw-plugin@2026.7.2
   docker exec -it xa-kb-gateway node dist/index.js plugins list
   ```

   Gateway 2026.9.2 的 catalog 目标正好是 2026.7.2，所以这里不带 `npm:` 前缀也能装到这一版。

3. 换回第 3 节的终态配置，`docker compose down && docker compose up -d`。

4. 验证：`channels list` 为 `WeCom default: installed, configured, enabled`；`agents list --bindings` 有 `kbagent`；日志 `Authentication successful`。

控制台：`ssh -N -L 18790:127.0.0.1:18790 YOUR_LINUX_USER@SERVER`，浏览器开 `http://127.0.0.1:18790/`。

## 5. 知识文档与索引

只有 `AGENTS.md`、`SOUL.md`、`IDENTITY.md`、`USER.md`、`HEARTBEAT.md`、`MEMORY.md` 会被注入，其它 `*.md` 不会。资料约 38 个文件、13.6 万字符，放不进 `AGENTS.md`，所以做法是：`AGENTS.md` 里放文件名索引，模型每次先 `read` 相关文件再答。

知识文件放在虚机 `xa-kb/workspace/` 根目录（与 `AGENTS.md` 同层）。在 `xa-kb` 目录运行下面的脚本，生成索引并重写 6 个规则文件；以后每新增或改名一个 `*.md` 都重跑：

```bash
python3 - <<'PY'
from pathlib import Path
ws = Path("workspace")
fixed = {"AGENTS.md", "SOUL.md", "IDENTITY.md", "USER.md", "HEARTBEAT.md", "MEMORY.md"}
docs = sorted(p.name for p in ws.glob("*.md") if p.name not in fixed)
if not docs:
    raise SystemExit("workspace 根目录没有知识文件")
agents = [
    "# 规则", "",
    "你是企业微信资料问答机器人。员工每发一条问题，都必须用中文给出文字回复，禁止沉默。", "",
    "回答前先根据下面的文件名索引，调用 read 读取相关的知识文件，可以读多份。只用读到的正文作答。资料里没有的，回复「资料里没有」。", "",
    "不要 read 本文件、SOUL.md、IDENTITY.md、USER.md、HEARTBEAT.md、MEMORY.md。不要 write，不要 edit，不要建单。", "",
    "## 知识文件索引", "",
] + [f"- {name}" for name in docs]
files = {
    "AGENTS.md": "\n".join(agents),
    "SOUL.md": "# 工作原则\n\n先 read 索引里的知识文件，再简短回答。每条提问都要有文字回复。",
    "IDENTITY.md": "# 身份\n\n名称：文档助手。根据工作区知识文件回答问题。",
    "USER.md": "# USER\n\n同时服务多名员工。不要建立个人档案，不要把姓名或部门写进本文件。",
    "HEARTBEAT.md": "# HEARTBEAT\n\n心跳不要主动发消息。员工提问不受本文件限制，必须按 AGENTS.md 回复。",
    "MEMORY.md": "# MEMORY\n\n资料在同目录的其它 Markdown 文件中。回答前按 AGENTS.md 的索引 read，不要把正文写入本文件。",
}
for name, text in files.items():
    (ws / name).write_text(text + "\n", encoding="utf-8")
print(f"indexed {len(docs)} files")
PY
sudo chown -R 1000:1000 workspace && docker compose restart
```

然后企微里单独发 `/new`，再发 `/context detail`：`AGENTS.md` 无 `TRUNCATED`，`Skills list` 为 0。再问一个只有某份纪要里才有的数字验证。

Windows 上 `F:\workspace\xa-kb` 的初稿（规则写「不要调用任何工具」、`MEMORY.md` 空索引、`HEARTBEAT.md` 要求静默）会让机器人不回文字，不要拿来覆盖虚机上的文件。

## 7. 排障

| 现象 | 处理 |
| --- | --- |
| `curl 18790` 被重置，日志只有 `plugin not installed` | `enabled: true` 早于安装：按第 4 节第 1 步去掉 entries，起来后再装 |
| `config validate` 报 7 条 missing env | `docker exec` 要带 `-e VAR="$(tr -d '\n' < ./secrets/x.txt)"`；路径用 `./secrets/` |
| 企微完全没有文字 | 规则文件还是初稿（禁止工具 / 要求静默），按第 5 节重写后 `/new` |
| 答「资料里没有」或答非所问 | 没放开 `read`，或知识文件不在 workspace 根目录，或索引没重跑 |
| 有「思考中」但一直没有正文 | `timeoutSeconds` 还是 20，改 120 后 `restart` |
| `docker exec -it` 报没有 TTY | 改用 `-i` |
| 两个机器人抢连接、重复回复 | 两套 Gateway 用了同一 Bot，本套换新 Bot |
