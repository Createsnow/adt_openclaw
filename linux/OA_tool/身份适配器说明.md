# 身份适配器说明

适用对象：已经理解 [企微到OA身份与数据流.md](企微到OA身份与数据流.md) 中的 Redis `idmap` 路径，准备把加密 `open_userid` 转成 OA 人员 id 的工程师。

OA 桥接部署、Compose、entrypoint、`oa_workflow` 错误码仍以 [OA Workflow Bridge（Redis）接入手册.md](OA%20Workflow%20Bridge（Redis）接入手册.md) 为准。企微通道安装仍以 [../WeCom 通道插件接入手册.md](../WeCom%20通道插件接入手册.md) 为准。Ecology 两条人事接口对照见 [Ecology 流程创建 API 说明.md](Ecology%20流程创建%20API%20说明.md) 第四步与 [../Aidy 现网加固与演进全景.md](../Aidy%20现网加固与演进全景.md) 第 7 节；**本文只覆盖用工号点查人员 id**。

**本文只讲：** 身份转换层怎么工作、转换 API、请求无重试与失败回执、包文件、桥接注入与凭据。适配器不是第二套映射方案，也不是模型可调 tool。

**代码已合入并验证通过。** 身份权威：Redis `idmap` 缓存人员 id，miss 时由本适配器现查再写入。适配器是 Gateway 进程内的 npm 包，**不是**单独服务器。`bridge-config.json` 为 `identity.adapter=on` 且 `identity.store=redis`；须注入自建应用凭据。`active=true` 仍走原 OA 切流门槛。

## 2. 为何单独做适配器

终态若直接拿 `requesterSenderId` 当 OA 工号会找不到人。现网它是 `wo` 开头的加密 userid（`open_userid`）。

适配器补的是 **加密 userid → 工号 → 人员 id** 的转换层，并且把企微通讯录 API、**用工号点查人员 id**（`getHrmUserInfoWithPage`）都放在独立包里，**不要**塞进 `oa-workflow-bridge-redis/src/oa-client.mjs`。`tool.mjs` 在 `submit_confirmed` 会调桥接自己的 `hrm-profile.mjs`（`getHrmSimpleInfo`，部门 / 岗位 / 地点），那是建单链，不是本适配器。

```text
通道 wecom-openclaw-plugin
  → ctx.requesterSenderId = open_userid（加密串）
身份适配器（本文）
  → 明文 userid → 对齐 OA workcode → 数字人员 id → Redis idmap
OA 桥接 oa_workflow.prepare
  → 只消费 mappingCode → oaUserId（写入 pending.oaRequesterId）
OA 桥接 oa_workflow.submit_confirmed
  → Header `userid`（RSA）与 `xqsqr` = 同一人员 id
  → 另调 getHrmSimpleInfo 写 xqsqbm / gw / bgdd（hrm-profile.mjs，不是本适配器）
```

| 层 | 输入 | 输出 | 谁负责 |
| --- | --- | --- | --- |
| 通道 | `aibot_msg_callback.from.userid` | `requesterSenderId` | `wecom-openclaw-plugin`，**不改** |
| 适配器 | `open_userid`（仅内存） | `mappingCode` → 1–18 位 `oaUserId` | 已实现 `wecom-oa-identity-adapter`（`adapter=on` 时由桥接注入） |
| OA 桥接（身份） | `mappingCode` | Header `userid`（RSA）与 `xqsqr` = 同一数字人员 id | `oa-workflow-bridge-redis` 只 GET `idmap`，不自行转换 |
| OA 桥接（资料） | `pending.oaRequesterId` | `xqsqbm` / `gw` / `bgdd` | `hrm-profile.mjs` + `getHrmSimpleInfo`；不是本适配器 |

机器人 BotId / BotSecret **不能**拿来做转换。转换必须另建企业内部应用，用该应用的 `corpid` + `corpsecret` 换 `access_token`。通道凭据、转换凭据、OA 凭据是三套，不能混。

## 3. 稳定契约

适配器写回的数据必须让现有 `getMappedOaUserId` 能读懂，不要另搞一套键。

| 字段 | 规则 |
| --- | --- |
| 键 | `mappingCode` = SHA-256(`requesterSenderId`) 截前 24 位小写十六进制 |
| 值 | 仅 1–18 位数字 `oaUserId` |
| 禁止落盘 / Redis / 日志 | `open_userid`、明文 userid、工号、人事 PII、AppSecret、corpsecret |
| `xqsqr` / 建单 Header `userid` | 员工人员 id；不是接口账号、不是 `wo…`、不是 appid、不是工号。Header 走 RSA，表单写明文 |

进程形态：**独立 npm 包，由桥接 `prepare` 注入调用**。不注册模型可调 tool。官方通道插件目前不会把「已转换 userid」写入可信上下文，身份仍走 miss 再查再写 `idmap`，不要改成消息一进就解析人员。工单附件由桥接订 `message_received`（以及 `agent_turn_prepare` / `before_prompt_build`）收集本地路径，与身份转换无关。

## 4. 对照：文件预绑（历史）与现行 Redis

下表仅对照。现行权威是 `idmap`，不要双写。

| 项 | 文件预绑（历史对照） | 现行（本文适配器） |
| --- | --- | --- |
| 查找 | 只读映射文件 | GET `idmap`；miss 再转换 + 人事点查 |
| 企微转换 | 不需要 | 自建应用 `user/get`，回退 `openuserid_to_userid` |
| 人事查询 | 绑文件时手工点查 | 放适配器（`getHrmUserInfoWithPage`）；桥接不引入 **用工号点查**。提交前 `getHrmSimpleInfo` 是另一条链 |
| Redis `idmap` 谁写 | 不写 | 适配器写；桥接只 GET |
| 失败时员工看到 | 错误码 `OA_IDENTITY_MAPPING_REQUIRED`（**不**把 `mappingCode` 回给模型或员工） | `OA_IDENTITY_NOT_FOUND` / `WECOM_IDENTITY_ALIGN_MISMATCH` 等（同样不回 `mappingCode`） |
| 配置 | 历史映射文件已删除。现码写 `store=files` 会拒绝加载 | `adapter=on`，`store=redis` |

人事查询（用工号 → 人员 id）只在适配器里。**不要**在桥接 `oa-client.mjs` 再调 `getHrmUserInfoWithPage`。提交前部门 / 岗位 / 地点走桥接 `getHrmSimpleInfo`，对照见现网加固第 7 节。

## 5. 企微转换 API

适配器**不是单独进程**：`oa-workflow-bridge-redis` 在 `prepare` miss 时 `import` `resolve(senderId)`，跑在同一 Gateway 容器。

官方 token：[获取 access_token](https://developer.work.weixin.qq.com/document/path/91039)。官方转换：[自建应用与智能机器人的对接](https://developer.work.weixin.qq.com/document/path/101521)。读取成员：[user/get](https://developer.work.weixin.qq.com/document/path/90196)。

| 步骤 | 接口 | 输入 | 成功 |
| --- | --- | --- | --- |
| 1. 换 token | `GET https://qyapi.weixin.qq.com/cgi-bin/gettoken` | 自建应用 `corpid` + `corpsecret` | `access_token`；**官方有效 2 小时（7200 秒）**；适配器进程内缓存 **90 分钟**，到期前刷新 |
| 2. 主路径 | `GET https://qyapi.weixin.qq.com/cgi-bin/user/get` | token + `requesterSenderId`（现网加密串也可） | `userid` 当工号；扩展属性「工号」若存在则必须相等 |
| 3. 回退 | `POST https://qyapi.weixin.qq.com/cgi-bin/batch/openuserid_to_userid?access_token=` | `{ "open_userid_list": [senderId] }` | `userid_list[].userid` |

约束：

- 必须用**自建应用**的 `access_token`，不是机器人 Secret。
- 成员必须在该自建应用**可见范围**内。`user/get` 返回可见范围类 errcode（如 81013 / 60011）记 `WECOM_IDENTITY_OUT_OF_SCOPE`，**不再**回退 `openuserid_to_userid`。
- `openuserid_to_userid` 的 `invalid_open_userid_list`（含明文 userid 误进 batch）记 `WECOM_OPENUSERID_INVALID`。
- access_token 失效类 errcode 会清进程内 token 缓存并记 `WECOM_IDENTITY_TOKEN_FAILED`，不回退 batch。
- 一次最多 1000 条；运行时每次只转当前发送人一条。
- 日志只记 `errcode` / 是否命中 invalid 列表，不记 `open_userid` 和明文 userid。
- 每个 HTTP **只打一次**，超时 20 秒。`user/get` 得不到 `userid` 再走 `openuserid_to_userid` 是协议回退，不是对失败请求再打一遍。无重试与模型回执见第 8.1 节。

## 6. 明文与 OA 工号对齐

对齐策略 `userid_equals_workcode` **已验证通过**。现网通讯录账号与 OA 工号相同。

| 情况 | 动作 |
| --- | --- |
| 明文 userid **等于**该员工 OA `workcode` | 适配器内存里把 userid 当 `workcode`，再调人事接口并写 `idmap` |
| 扩展属性「工号」**存在**且不等于 `userid` | fail-closed（`WECOM_IDENTITY_ALIGN_MISMATCH`），禁止写入 `xqsqr` 或 Redis |
| **没有**扩展属性「工号」（属性名不是精确「工号」、或未配） | **把明文 userid 当 workcode** 去点查人事。这是现网已验证口径，不是漏检 |
| 明文 userid 等于 OA `loginid`，但 `workcode` 不同 | 不能直接查 `workcode`。有「工号」属性且对不上则 fail-closed；无该属性则会按上一行用 userid 去查，人事 `NOT_FOUND` 或查到别人时仍失败 |

## 7. OA 人事查询（用工号点查，放适配器，不放桥接）

| 项 | 要求 |
| --- | --- |
| 接口 | `POST https://adtekoa.com/api/hrm/resful/getHrmUserInfoWithPage` |
| Body | `{ "params": { "workcode": "<内存中的工号>" } }` |
| 认证 | 与现网实测一致：只带 `Content-Type: application/json; charset=utf-8`，**不带** `token` / `appid` / `userid`。须 OA 管理员把 Gateway 出口 IP 加入白名单。不要把这种无 Header 写法推广到 `applytoken` / `doCreateRequest` |
| 成功 | `code="1"` 且 `data.totalSize=1`，取 `data.dataList[0].id`（1–18 位数字） |
| 拒绝 | 0 条；多条；`status` ∈ 4/5/6/7；`accounttype=1` 次账号 |
| 超时 / 重试 | 单次 `fetch`，30 秒超时；失败**不**重打。见第 8.1 节 |
| PII | 整段 `dataList` 禁止写入日志、Redis、员工回复、仓库 |

适配器模块 **不能** `import` 桥接的 `oa-client.mjs`（避免转换和建单缠死）。人事点查不复制桥接的 RSA / token 逻辑。

## 8. `resolve` 流水线

唯一对外函数：`resolve(senderId)` → `{ mappingCode, oaUserId }` 或抛错。

| 序 | 动作 | 失败码（适配器内部） |
| --- | --- | --- |
| 1 | 校验 `senderId` 非空；计算 `mappingCode` | `WECOM_IDENTITY_INVALID_SENDER` |
| 2 | GET `idmap` | 命中则直接返回，不调企微、不调人事 |
| 3 | GET `idmiss` | 近期失败则直接抛出负缓存错误码，不调企微、不调人事 |
| 4 | 读 `WECOM_IDENTITY_CORPID` / `WECOM_IDENTITY_SECRET` | **`OA_IDENTITY_NOT_CONFIGURED`**（主进程没有这两项；宿主机有 txt 不够） |
| 5 | `user/get`，失败再 `openuserid_to_userid` | `WECOM_OPENUSERID_INVALID` / `WECOM_IDENTITY_OUT_OF_SCOPE` / `WECOM_IDENTITY_TOKEN_FAILED` |
| 6 | 明文 userid 与 `workcode` 对齐 | `WECOM_IDENTITY_ALIGN_MISMATCH` |
| 7 | `getHrmUserInfoWithPage`（工号只在内存） | `OA_IDENTITY_NOT_FOUND` / `OA_IDENTITY_AMBIGUOUS` / `OA_IDENTITY_INACTIVE` / `OA_IDENTITY_LOOKUP_FAILED` |
| 8 | `SET EX idmap` | 只写数字 id + `cachedAt`。工单附件仍在本机 staging，不进身份缓存 |

缓存命中：0 次外部 HTTP。企微失败：不调人事。`open_userid` 只在适配器内存里停留一次请求。

桥接侧：`senderId` **不**写入 pending JSON。适配器失败则不写 pending，把错误码回给 Agent（形态见第 8.1 节）。

### 8.1 请求无重试、超时与模型回执

适配器对企微、人事 **同一 HTTP 请求不做自动重试**（无 retry / backoff）。超时、网络失败、非 JSON、业务拒绝，都立刻抛错。代码与测试均无重试循环。

| 调用 | 超时 | 失败后 |
| --- | --- | --- |
| 企微 `gettoken` / `user/get` / `openuserid_to_userid` | `AbortSignal.timeout(20000)` | 不重打同一接口 |
| OA 人事 `getHrmUserInfoWithPage` | `AbortSignal.timeout(30000)` | 不重打同一接口 |

不要把下面几件事当成「已经重试过」：

| 行为 | 实际 |
| --- | --- |
| `lookupUserid`：`user/get` 未得到 `userid` 再走 `openuserid_to_userid` | 加密 userid 的协议回退，不是对失败请求再打一遍 |
| token 进程内缓存 90 分钟 | 缓存命中跳过 `gettoken`；`gettoken` 失败仍不重试 |
| `SET EX idmiss`（默认 10 分钟） | **挡住**再试：期间再次 `prepare` 直接抛上次错误码，不打企微 / 人事。`OA_IDENTITY_NOT_CONFIGURED` / `WECOM_IDENTITY_TOKEN_FAILED` **不写** idmiss，避免刚补凭据或换 token 后仍被挡 |

失败路径：`resolve()` 抛 `IdentityError` → 桥接 `getMappedOaUserId` 转成 `OAClientError`（保留 `code` 与英文 `message`）→ `oa_workflow.prepare` 的 tool 回执。身份失败 **不写 pending、不调建单**。`docker logs` 无这些码；抽会话 jsonl 见第 10.7 节。

回给模型的 JSON 形态（示例为人事超时 / 网络失败）：

```json
{
  "ok": false,
  "code": "OA_IDENTITY_LOOKUP_FAILED",
  "message": "OA HR request failed"
}
```

工具 JSON **不含** `mappingCode`、SenderId、HTTP 原文、明文 userid、工号。10 分钟内再 `prepare` 时 `code` 仍是上次那码，`message` 为 `WeCom identity lookup recently failed`。

| 场景 | 回给模型的 `code` |
| --- | --- |
| 转换凭据未注入 | `OA_IDENTITY_NOT_CONFIGURED` |
| SenderId 为空 | `WECOM_IDENTITY_INVALID_SENDER` |
| 企微 token 失败 | `WECOM_IDENTITY_TOKEN_FAILED` |
| 可见范围外 | `WECOM_IDENTITY_OUT_OF_SCOPE` |
| 加密串无法转换 | `WECOM_OPENUSERID_INVALID` |
| 工号对不齐 | `WECOM_IDENTITY_ALIGN_MISMATCH` |
| 人事查不到人 | `OA_IDENTITY_NOT_FOUND` |
| 同一工号多人 | `OA_IDENTITY_AMBIGUOUS` |
| 离职 / 次账号 | `OA_IDENTITY_INACTIVE` |
| 超时 / 网络 / HTTP 拒绝 / 非 JSON | `OA_IDENTITY_LOOKUP_FAILED` |
| `idmiss` 命中 | 上次写入的短错误码 |

员工可见口径运行时在 `workspace-rules/AGENTS.md`（人读完整模板仍在 `TICKET_STATUS_BANNER.md`，Agent 不 read）：名单内的身份码（含 `WECOM_IDENTITY_INVALID_SENDER`）显示「还不能提交到 OA / 账号还没开通提交权限」；`OA_IDENTITY_LOOKUP_FAILED`、`OA_IDENTITY_AMBIGUOUS`、`WECOM_OPENUSERID_INVALID` 不在该名单，落到「确认准备失败」。`prepare` 与 `submit_confirmed` 都用同一块（回执 `hintZh` 可原样输出）。不要向员工展示英文 `message`、内部码或「映射」。`oa_workflow` 错误码与 `hintZh` 总表见 OA Redis 手册第 7.5 节。

### 9.1 Redis 键（仅身份缓存）

适配器 **不读不写** `pending` / `ledger` / `idx`。

| 键 | 值 | TTL |
| --- | --- | --- |
| `{prefix}:idmap:{mappingCode}` | JSON `{ "oaUserId": "数字", "cachedAt": "ISO" }` | `SET EX`，默认 24h |
| `{prefix}:idmiss:{mappingCode}` | 短负缓存，值只是错误码 | 例如 10 分钟，避免打爆企微 / 人事 |
| `pending` / `ledger` / `idx` | 不碰 | 仍由桥接管理；`ledger` / `idx` **不设** TTL，`pending` 带宽限 `PX` |

`keyPrefix` 可与桥接相同（默认 `oa-workflow-bridge`），靠 key 名区分；多环境仍应改前缀。生产 Redis 仍要 AOF + `noeviction`。`idmap` 的 EX 是过期，不是 LRU 淘汰。

## 10. 在 OpenClaw 里怎么配

适配器**不是**企微通道那种「写进 `openclaw.json` 就能打开」的插件。真正开关在桥接的 `bridge-config.json`。`openclaw.json` 默认**什么都不加**；凭据不进 json。

官方插件字段仍以 [Plugins](https://docs.openclaw.ai/tools/plugin) 为准：`plugins.allow` 是排他白名单；`plugins.deny` 优先；`load.paths` 改完要重启 Gateway；workspace 来源插件默认关，须 `entries.<id>.enabled: true`。本节只写本适配器与那套字段的关系。

### 10.1 配置落在哪（不要找错文件）

| 文件 | 配什么 | 不配什么 |
| --- | --- | --- |
| **`openclaw.json`** | **默认不改。** 可选：把适配器登记进 `allow` / `load.paths` / `entries.enabled`，仅用于 `plugins list` 与 logger | **不要**写 `identity.adapter`、corpid、corpsecret、`idmap`、`alignMode`。**不要**把适配器 id 或任何转换工具写入 `tools.alsoAllow` |
| **`bridge-config.json`** | **真正开关：** `identity.adapter`、`identity.store` | 不要写企微自建应用 Secret |
| **`adapter-config.json`** | 对齐策略、缓存 TTL、企微 / OA `baseUrl` | 不要抄 OA `appId` / 公钥。是否 `import` 只看 `identity.adapter` |
| **Docker secrets + entrypoint** | `WECOM_IDENTITY_CORPID` / `WECOM_IDENTITY_SECRET` | 不要写进 `openclaw.json` 或 compose `environment:` |
| **`WECOM_OA_IDENTITY_ADAPTER_PATH`** | 仅当适配器**不**在桥接并列目录时，指向适配器包根目录 | 并列部署时不必设 |

`plugins.entries.wecom-oa-identity-adapter.config` **配不了任何业务项**：`openclaw.plugin.json` 的 `configSchema.properties` 是空对象。官方 `entries.<id>.config` / `entries.<id>.env` 也不要用来塞 corpsecret。

### 10.2 `openclaw.json` 推荐默认：不加入适配器

桥接 `index.mjs` 在 `identity.adapter=on` 时按相对路径动态 `import`：

```text
../wecom-oa-identity-adapter/src/resolve.mjs
```

因此 **不必** 出现在 `plugins.allow`、`plugins.load.paths`、`plugins.entries`。Aidy 现网 `openclaw.json` 保持桥接手册 5.2 即可：

```json
"plugins": {
  "allow": [
    "oa-workflow-bridge-redis",
    "wecom-openclaw-plugin"
  ],
  "deny": [
    "codex"
  ],
  "load": {
    "paths": [
      "/home/node/.openclaw/extensions/oa-workflow-bridge-redis"
    ]
  },
  "entries": {
    "oa-workflow-bridge-redis": { "enabled": true, "hooks": { "allowConversationAccess": true } },
    "wecom-openclaw-plugin": { "enabled": true, "hooks": { "allowConversationAccess": true } },
    "codex": { "enabled": false }
  }
}
```

```json
"tools": {
  "alsoAllow": [
    "oa_workflow"
  ]
}
```

现网完整 `openclaw.json` 见 `../openclaw.json 配置参考.md` 第 15 节。`oa_workflow` 已在白名单；不要加入 `wecom_mcp`。适配器 id **仍然不要**出现在 `alsoAllow`。

| 项 | 要不要写 | 原因 |
| --- | --- | --- |
| `plugins.allow` 含 `wecom-oa-identity-adapter` | **否**（默认） | 桥接直接 import 文件，不经过插件加载器 |
| `plugins.load.paths` 含适配器目录 | **否**（默认） | 同上；改 `load.paths` 还要重启 Gateway |
| `plugins.entries.wecom-oa-identity-adapter` | **否**（默认） | `configSchema` 为空，没有可配项 |
| `tools.alsoAllow` 含适配器 id 或转换 API | **永不** | 适配器 **禁止** `registerTool`；模型不能调 `user/get` / 人事接口 |
| `channels.wecom` | 不变 | 转换凭据与 BotId/BotSecret 不是一套 |

部署：拷到 `~/aidy/extensions/wecom-oa-identity-adapter`（与桥接**同一层**，不要放进桥接目录里）。**完整 `docker run`（镜像名对齐、桥接与适配器两包都要装 `redis`）只在 OA Redis 手册 4.2 写全。** 不要只装桥接。`plugins.allow` **不必**加入适配器。路径示例：

```bash
cp -r "$REPO/OA_tool/wecom-oa-identity-adapter" \
  ~/aidy/extensions/wecom-oa-identity-adapter
```

容器内对应 `/home/node/.openclaw/extensions/wecom-oa-identity-adapter`。目录名必须是 `wecom-oa-identity-adapter`，相对路径才能解析。若必须换路径：

```sh

```

（值是**包根目录**，不是 `src/resolve.mjs`。写在 entrypoint 的 `exec` 之前。）

`plugins list` **看不到**适配器是预期，不是漏配。应看到 `oa-workflow-bridge-redis` 且 enabled。Gateway 日志仍是：

```text
[oa-workflow-bridge-redis] loaded (Redis state) from ...
```

`adapter=on` 后第一次 `prepare` 才会 `import` `resolve.mjs`。包不在并列目录、或 `WECOM_OA_IDENTITY_ADAPTER_PATH` 指错，这次调用失败，不必指望 `plugins list` 先报错。

### 10.3 可选：登记成 OpenClaw 插件（仍无 tool）

只为了 `plugins list` 出现、以及 `index.mjs` 打 `[wecom-oa-identity-adapter] loaded ... (no tools)`。**不能**代替 `bridge-config.json` 的 `identity.adapter=on`，也**不会**让桥接多一次 `resolve`。

```json

    "oa-workflow-bridge-redis",
    "wecom-oa-identity-adapter",
    "wecom-openclaw-plugin"
  ],
  "load": {

  "entries": {
    "oa-workflow-bridge-redis": { "enabled": true, "hooks": { "allowConversationAccess": true } },
```

- 已有 restrictive `plugins.allow` 时，漏写 id 会被 allowlist 拦住（官方：`blocked by allowlist`）。

- `entries.<id>.enabled: true` 仍要写（workspace / 本地扩展默认关）。
- **仍然不要**出现在 `tools.alsoAllow`。
- `entries.wecom-oa-identity-adapter.config` 保持不写（schema 为空；写了会被官方判 Invalid）。

未打开 `identity.adapter` 时不要走本可选路径，避免误以为「插件 enabled = 身份已开」。

### 10.4 真正开关：`bridge-config.json`

路径：`~/aidy/extensions/oa-workflow-bridge-redis/bridge-config.json`（容器内同一相对路径）。**不在** `openclaw.json`。

现行（适配器已验证）：

```json
"identity": {
  "adapter": "on",
  "store": "redis"
}
```

不要写 `"store": "files"`：`config.mjs` 只允许 `redis`，其它值加载失败（`identity.store must be redis`），插件起不来。

| 字段 | 取值 | 作用 |
| --- | --- | --- |
| `identity.adapter` | `on` \| `off` | `on`（**省略时默认**）：`import` 适配器 `resolve(senderId)`。`off`：**不**调用适配器、**不**读映射文件，`prepare` 回 `OA_IDENTITY_MAPPING_REQUIRED`。现网必须 `on` |
| `identity.store` | 只允许 `redis` | 省略时默认 `redis`。先 GET `idmap`，miss 再 resolve。**没有** `files` 路径 |

现行用 `on` + `redis`。缺 `WECOM_IDENTITY_CORPID` / `WECOM_IDENTITY_SECRET` 时补凭据，回执是 `OA_IDENTITY_NOT_CONFIGURED`；**不要**改成 `adapter=off` 指望读映射文件。`active=true` 与 `oa_workflow` 白名单仍走原切流门槛，打开适配器**不能**代替它们。

改完不必改 `openclaw.json`；重启 Gateway 使桥接重新读 json（或确认当前版本是否热加载该文件后，仍以重启为准，避免半开）。

### 10.5 适配器自己的 `adapter-config.json`

路径：`~/aidy/extensions/wecom-oa-identity-adapter/adapter-config.json`。桥接注入时 `createIdentityResolverFromFiles` 读这一份。

| 字段 | 要求 |
| --- | --- |
| `alignMode` | 必须 `userid_equals_workcode`，其它值加载失败 |
| `wecomBaseUrl` | 必须恰好 `https://qyapi.weixin.qq.com` |
| `oaBaseUrl` | 必须恰好 `https://adtekoa.com` |
| `wecomTokenCacheMs` | 默认 `5400000`（90 分钟）。官方 token 7200 秒，不要用满再刷 |
| `cache.store` | 必须 `redis`（代码强制） |
| `cache.keyPrefix` | 默认 `oa-workflow-bridge`，与桥接 `redis.keyPrefix` 对齐 |
| `cache.ttlHours` | `idmap` 的 `SET EX`，默认 24 |
| `cache.missTtlSeconds` | `idmiss` 负缓存，默认 600 |

不要在本文件写 `enabled`、`appId`、`publicKeySpkiBase64`：身份开关只认桥接 `identity.adapter`；OA 应用许可证与 RSA 公钥只在 `bridge-config.json`（建单 / `getHrmSimpleInfo` 才用）。人事点查不带这两项。

人事点查不读 `OA_API_USER_ID` / `OA_APP_SECRET`。建单仍由桥接用进程环境里的这两项，不要把 AppSecret 写进本文件。

### 10.6 Docker secrets（与机器人那两个分开）

| 宿主机 | 容器 | 环境变量 |
| --- | --- | --- |
| `~/aidy/secrets/wecom_identity_corpid.txt` | `/run/secrets/wecom_identity_corpid` | `WECOM_IDENTITY_CORPID` |
| `~/aidy/secrets/wecom_identity_secret.txt` | `/run/secrets/wecom_identity_secret` | `WECOM_IDENTITY_SECRET` |

entrypoint 在 `exec` **之前** `export`。compose `secrets` 增加对应 `file:`。不要写进 `openclaw.json`，不要复用 `wecom_bot_secret` / `AIDY_IT_WECOM_BOT_SECRET`。

```bash

printf '%s' '自建应用corpsecret' > ~/aidy/secrets/wecom_identity_secret.txt
chmod 600 ~/aidy/secrets/wecom_identity_corpid.txt ~/aidy/secrets/wecom_identity_secret.txt
sudo chown 1000:1000 ~/aidy/secrets/wecom_identity_corpid.txt ~/aidy/secrets/wecom_identity_secret.txt
```

Gateway compose **增量**（其它 secret 仍以 OA Redis 手册 5.5.1 为准）：

```yaml

    secrets:
      - wecom_identity_corpid
      - wecom_identity_secret

  wecom_identity_corpid:
    file: ./secrets/wecom_identity_corpid.txt
  wecom_identity_secret:
```

entrypoint，插在已有 OA export **之后**、`exec node ...` **之前**：

```sh

export WECOM_IDENTITY_SECRET="$(tr -d '\n' < /run/secrets/wecom_identity_secret)"
```

**不要**把这两项写进 compose 的 `environment:`（`docker inspect` 会看到 corpsecret）。缺文件且脚本是 `set -eu`、同时 compose **已经声明**这两项时，容器会 Restarting。compose **没声明**时容器能起来，员工看到「还不能提交到 OA」，工具回执是 `OA_IDENTITY_NOT_CONFIGURED`。

宿主机有 `~/aidy/secrets/wecom_identity_*.txt` **不等于**已注入。必须同时：① compose 声明并 `file:` 指向这两份 txt；② entrypoint 在 `exec` 前 export；③ `cd ~/aidy && docker compose down && docker compose up -d`（只 `restart` 不够；Redis 保持 up）。

## 11. OA 桥接如何注入适配器

`oa-client.mjs`、`mapping.mjs`、`state-store.mjs`、`attachments.mjs` **不**承担企微转换或用工号点查人员 id。提交前部门 / 岗位 / 地点由桥接 `hrm-profile.mjs` 经 `OAClient.authenticatedRequest` 调 `getHrmSimpleInfo`（见现网加固第 7 节），不是本适配器。

## 14. 禁止事项

- 不要把 `openuserid_to_userid` 或人事现查做成模型可调 tool（不是通用 HTTP 工具）。
- 不要在 `oa-client.mjs` / `tool.mjs` 里直接调企微通讯录 API。
- 不要用机器人 `BotSecret` 当自建应用 `corpsecret`。
- 不要假设 `requesterSenderId` 等于 OA 工号；现网已证明不是。
- 不要把明文 userid、工号、`wo…` 或接口账号人员 id 写入 `xqsqr`、建单 Header `userid`、Redis、日志或员工回复。
- 不要文件和 Redis **双写**身份当两套权威；权威只认 `idmap`。
- 不要给 `ledger` / `idx` 设 Redis TTL（`pending` 的宽限 `PX` 由桥接自己管，适配器不碰）；不要对身份键 `SCAN` / `KEYS`。
- 不要依赖现网人事接口无认证可查去扫全员花名册；适配器每次只查当前发送人一条。人事点查与现网实测一致（无 `token` / `appid` / `userid`），不要把这种无 Header 写法推广到 `applytoken` / `doCreateRequest`。
- 不要把适配器做成单独 HTTP 服务或再开一个 compose 容器。
- 不要把工单附件 staging 和身份 `idmap` 混在一个目录。
- 不要用满企微 token 的 7200 秒才刷新；适配器缓存 90 分钟。
- 不要对企微 / 人事身份 HTTP 做自动重试；超时失败立刻回执。靠 `idmiss` 负缓存挡住短时间再打，不要循环打接口。
- 不要把 `user/get` → `openuserid_to_userid` 当成「已经重试过」。
- 不要在缺 `WECOM_IDENTITY_CORPID` / `WECOM_IDENTITY_SECRET` 时改 `"adapter": "off"` 指望读映射文件；`off` 只回 `OA_IDENTITY_MAPPING_REQUIRED`，`store=files` 会拒绝加载。缺凭据应补注入，回执是 `OA_IDENTITY_NOT_CONFIGURED`。
- 不要只在宿主机写 `wecom_identity_*.txt` 却不挂 compose、不在 entrypoint `export`（会 `OA_IDENTITY_NOT_CONFIGURED`）。
- 不要用安装手册里尚无 `WECOM_IDENTITY_*` 的 entrypoint 整段覆盖已接 OA 的 `entrypoint.sh`（工位 6.4.2 / Linux 第 7 节第一份）。
- 不要用 `docker logs | grep OA_IDENTITY` 判断没调 `prepare`；回执在会话 jsonl（第 10.7 节）。
- 不要把页脚「身份待核验」当成 OA 申请人未映射。
- 不要在 `openclaw.json` 里寻找 `identity.adapter` / `alignMode` / corpsecret；开关只在 `bridge-config.json`。
- 不要把 `wecom-oa-identity-adapter` 写入 `tools.alsoAllow`，也不要为它填写 `plugins.entries.*.config` 或 `entries.*.env` 来塞凭据。
- 不要把 `plugins.entries.wecom-oa-identity-adapter.enabled: true` 当成身份已打开。
- 不要在 `active=false` 时改 `AGENTS.md` 声称 OA 已通。
- 不要按姓名模糊匹配申请人；不要让员工对话自报工号作为正式绑定方案。
- 不要把 `~/aidy/secrets/` 提交到 git。
