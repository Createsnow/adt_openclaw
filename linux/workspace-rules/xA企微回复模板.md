# xA 企微回复模板

员工可见正文的编辑权威。运行时副本在 `workspace-rules/AGENTS.md`「用户可见回复」。改任何一句必须同步 `AGENTS.md`。短标题只作识别，不复述全文。  
状态 emoji（`📋` `✅` `⚠️` `🗑️` `❌` `⏳` `ℹ️` `🔍`）与 `**` 之间留一个空格。分隔线用 `---`，**前后必须各空一行**；紧贴上一行时企微会把问题/地点放大成标题。本会话确认卡：问题 / 地点 / 附件写完后空一行，再写补充引导句（不要编号、不要加粗），再空一行、`---`、再空一行、再写 `**请回复**`；头行必须是 `📋 **当前工单**`。无附件用「内容不对或还缺信息，直接再写一句，或发图片、文档。」；已有附件用「还可以继续改文字，或再发图片、文档。」。缺 `---`、把 `**请回复**` 写成「请回复」、把头行写成「📋 当前工单」都是错的。到 `2. 取消` 结束，不要 24 小时、不要口令区下方的 `---`，不要写成 `3. 补充`，不要问「还需要补充吗」。拦截卡不要写这两句。拦截卡：口令区上下各一条 `---`（同样前后空行），下方保留不能补图和 24 小时。区内先写 `**请回复**`，再写 `1.` `2.`（紧挨、点后空一格，不要空行、不要缩进）。口令本身不要加粗或代码标记。地点 1–6 等追问不要套这套操作区。  
插件回执 `hintZh`：无对应确认卡 / 拦截卡 / 提交成功模板时原样发给员工。现网 **不支持按 OA 工单号查询**，不要向员工要工单号。

回显只抄工具回执，不要解析 `systemName`，不要写工单类型 / 所属系统：

| 字段 | 来源 |
| --- | --- |
| 问题 | 只抄回执 `summary`（员工原话开头。短的全展示；长的已带 `...`）。不要贴 `problemDescription` |
| 地点 | 顶层 `location`（或 `prepare.summary.location`）。没有则不写「地点」行 |
| 附件 | `imageCount` / `documentCount`。都为 0 则不写「附件」行 |

附件行写法：`📎 附件：2份图片、1份文档`（有图报图，有文档报文档，1 也要写）。不要用合计 `attachmentCount`。

Emoji 词表（一对一，不要混用）：`🛠️` 品牌；`📝` 已记下 / 还差字段（短卡头行 `📝 **当前工单**`）；`💬` 问题；`📍` 地点；`📎` 附件；`📋` 待确认工单（确认卡头行 `📋 **当前工单**`，只报单，不要写成「请确认后提交」）；`✅` **仅**提交成功；`⚠️` 拦截 / 须先处理；`🗑️` 已取消；`⏳` 过期；`❌` 提交失败；`🔍` 查进度；`🎫` 工单号；`👤` 处理人；`ℹ️` 仅「已确认但 OA 还没建成」。

## 5. 本会话待确认（无附件）

头行只描述这张单，必须写成 `📋 **当前工单**`（`**` 不要省）。`💬 问题：` 用原话开头：短的全展示（`电脑死机`），长的加 `...`，不要把几百字贴上来，也不要改写成另一句。问题 / 地点 / 附件写完后必须空一行，再写补充引导句（不要编号、不要加粗），再空一行，再写 `---`，再空一行，再写 `**请回复**`。无附件用「内容不对或还缺信息，直接再写一句，或发图片、文档。」；已有附件用「还可以继续改文字，或再发图片、文档。」。`---` 紧贴上一行时字会变大。缺 `---` 或写成「请回复」都是错的。到 `2. 取消` 结束，不要 24 小时，不要写成 `3. 补充`，不要问「还需要补充吗」。差必填用 `📝 **当前工单**`，不要套本卡。

```text
📋 **当前工单**

💬 问题：电脑死机
📍 地点：智园

内容不对或还缺信息，直接再写一句，或发图片、文档。

---

**请回复**
1. 确认提交
2. 取消
```

**错**（缺 `---`、缺 `**`，不要这样发）：

```text
📋 当前工单

💬 问题：电脑死机
📍 地点：智园
请回复
1. 确认提交
2. 取消
```

**错**（`---` 紧贴补充引导句，企微会把上一行放大）：

```text
内容不对或还缺信息，直接再写一句，或发图片、文档。
---
**请回复**
```

一次贴很长，或断续多轮已经并进描述。卡片只露开头：

```text
📋 **当前工单**

💬 问题：4 个厂区同时用一套系统接单号...

内容不对或还缺信息，直接再写一句，或发图片、文档。

---

**请回复**
1. 确认提交
2. 取消
```

无 `location` 时删掉「地点」行。OA / MES 等通常没有地点：

```text
📋 **当前工单**

💬 问题：OA 待办打不开

内容不对或还缺信息，直接再写一句，或发图片、文档。

---

**请回复**
1. 确认提交
2. 取消
```

确认卡上员工回「不用了」「不用补充」「好的」「可以」「OK」「没问题」「就这样」：不要提交、不要取消，重发确认卡前先写：

```text
还没有提交哦。
想交请回「1」或「确认提交」，想作废请回「2」或「取消」。
「不用了」我分不清你是想交还是想取消。
```

然后空一行，再重发本会话确认卡。

员工把补充引导句整句发回来（「内容不对或还缺信息…」或「还可以继续改文字…」），或回 `3` / `请回复`：不是操作，原样重发确认卡，不要请改口。不要把引导句当成第 3 个口令。

## 15. 提交失败

`prepare` 与 `submit_confirmed` 的身份未映射用同一块。回执若带 `hintZh` 且下面没有对应模板，原样输出 `hintZh`，不要贴英文 `message`。不要对员工说「映射」「现网」。失败码 → 中文只在插件 `hintZh` 写全（OA Redis 手册 **7.5**）；本文件只保留有独立排版的块。

账号未开通提交权限（身份未映射码，含 `WECOM_IDENTITY_INVALID_SENDER`）：

```text
❌ **还不能提交到 OA**
> 原因：账号还没开通提交权限，请联系管理员
```

提交未开通（pending 还在）：

```text
ℹ️ **已确认，但还不能创建 OA 工单**

👤 处理人：郑鹏程
```

需人工核对：

```text
⚠️ **OA 需要人工核对**
🎫 工单号：1504371
```

其他明确失败（含 `PARAM_ERROR` / `OA_CREATE_REJECTED` / `HTTP_*` / `SYSTEM_NOT_ALLOWED` / `DRAFT_INVALID` / `HANDLER_NOT_CONFIGURED` / `ATTACHMENT_FIELD_NOT_CONFIGURED` / `REDIS_UNAVAILABLE` / `WORKFLOW_NOT_CREATEABLE` / `PREFLIGHT_FAILED`）：**优先原样输出 `hintZh`**（类型/系统对不上、OA 拒绝、缺处理人等已经是可行动中文，不要一律改成「请稍后重试」）；没有 `hintZh` 才用：

```text

```

## 固定块

| 块 | 原文 |
| --- | --- |
| 成功（无下一张） | `✅ **已提交到 OA**` + `💬 问题：…` + 地点/附件（有则写） + `🎫 工单号：…` + `👤 处理人：…` |
| 成功（还有当前单） | `✅ **上一张已交到 OA**` + 工单号/处理人 + `---` + 当前单确认卡或差必填短卡 |
| 取消（无下一张） | `🗑️ 好的，这张单已取消。` + `有新问题直接发给我。` |
| 取消（还有当前单） | `🗑️ **上一张已取消**（问题）` + `---` + 当前单确认卡或差必填短卡（3 / 4b / 4c / 4d） |
| 分隔 | `---` 前后各空一行；本会话确认卡只在口令区上方一条；拦截卡上下各一条 |
| 本会话确认 | `📋 **当前工单**` + 问题 / 地点 / 附件 + 空行 + 补充引导句 + 空行 + `---` + 空行 + `**请回复**` + `1. 确认提交` / `2. 取消`（引导句不要编号；无附件用「内容不对或还缺信息…」，有附件用「还可以继续改文字…」；`---` 前后必须空行，否则字会变大；`**` 不要省） |
| 接力确认 | 上一张结果 + 空行 + `---` + 空行 + 同一张确认卡（头行仍是 `📋 **当前工单**`，不要另写催促语） |
| 拦截 | `⚠️ **还有一张未提交的确认单**` + 上一张 / 刚才说的（分行，不要斜杠拼接） + 空行 + `---` + 空行 + `**请回复**` + `1. 确认提交上一张` / `2. 取消上一张` |
| 请改口 | `还没有提交哦。` + 请回 1 / 2；「不用了」分不清交还是取消 |
| 不按号查询 | `目前还不能按工单号查询处理进度。` + 无 pending 的 `hintZh` |
| 建单前附件过期 | `⏳ 刚才的图片或文件已过期，请重新发送。` |
| 附件回执 | 优先原样输出回执 `hintZh`（`📎 已收到 2份图片、1份文档`）；没有 `hintZh` 再按计数手写 |
| 弱提示 | 仅拦截卡：不能补图、24 小时用引用。本会话确认卡不要弱提示、不要 24 小时；补充引导句放在 `---` 上方，不是弱提示 |
| 查进度空 / 已提交列表 | 无 pending 时原样输出 `PERSON_STATUS.hintZh`（条数 + 最多 5 条工单号）。不要问工单号、不要查 OA 进度 |
| 查进度对账中 | 顶层或 `pending.code` 为 `RECONCILIATION_REQUIRED`：用「OA 需要人工核对」块，不要确认卡 / 拦截卡 |
