# 工单映射规则

运行时副本已写入 `AGENTS.md`（会话开始注入）。Agent **禁止**再 `read` 本文件。改关键词或匹配顺序时必须同步 `AGENTS.md`。

给每张**新工单**在 `prepare` 之前匹配两件必填事：**工单类型、所属系统**。建议责任人只作状态卡参考；模型不要传人员 id。插件按所属系统写入 OA `clry`。匹配顺序与失败边界以本文为准。

`oa_workflow` 不读本文。问候、进度查询、**同一张还在追问或待确认的单**的补充不要重新匹配。已取消、已提交、确认过期之后即使同一会话也是新工单，必须重新匹配，不得沿用上一张的地点 / `systemName`。

## 产出

| 产出 | 给谁 | 是否传给 OA |
| --- | --- | --- |
| 工单类型 `ticketType` | `oa_workflow` draft | 是（类型值） |
| 所属系统 `systemName` | `oa_workflow` draft | 是 |
| 建议责任人 | 员工可见「处理人」 | **否**（姓名不上 OA；插件另写 `clry` 数字 id） |

```text
员工企微发消息
  → 按本文关键词 + ROUTING_RULES.md 系统清单匹配
        唯一命中 → ticketType / systemName → 整理 draft → prepare
        零条 / 多条 → 不猜、不 prepare；请员工确认区域和所属系统
  → 规则到此结束；确认 / 建单不再查本文
```

## 权威来源

- 运行时权威：已注入的 `AGENTS.md`。本文与 `ROUTING_RULES.md` 供人编辑，须与 `AGENTS.md` 保持一致。`systemName` 必须与当前类型清单完全一致，否则插件拒绝。
- 不要把 JSON 导出文件或在线表格当规则源。

## 工单类型关键词

判定时：**完整短语、明确系统名、故障词优先于需求词。** 员工明确说出工单类型时，以明确选择为准。同时命中多个类型且无法唯一判断时必须确认。

- 运维支持：`故障｜异常｜报错｜无法｜不能｜失败｜坏了｜卡顿｜黑屏｜蓝屏｜死机｜断网｜不工作｜求助｜支持`
- 权限申请：`申请权限｜权限申请｜授权｜开通账号｜开通权限｜账号开通｜访问权限｜角色权限｜菜单权限｜申请开通`  
  单字「申请」「账号」不够。例如「申请看一下电脑开不了机」按运维支持，不按权限申请。
- IT需求：`IT需求｜业务需求｜新增功能｜需求开发｜数据处理｜流程新建｜流程优化｜系统集成｜集成对接`  
  单独的「优化」「开发」「改造」「对接」不够，除非员工明确说这是需求而不是故障或二开报修。

## 问题关键词库

长关键词、明确系统名优先。

- OA系统：`OA｜OA审批｜OA流程｜OA表单｜待办｜门户｜OA门户`  
  单独的「流程」不够（避免和 IT 需求的流程新建抢命中）。
- 企业微信：`企业微信｜企微｜微信工作台｜企微机器人｜通讯录`  
  不要把「群聊」当成企业微信故障。
- ERP（金蝶）系统：`ERP｜金蝶｜K3｜云星空｜财务系统｜供应链`
- 邮箱系统（国内）：`邮箱｜邮件｜Outlook｜收件｜发件｜退信`
- MES系统：`MES｜报工｜过站｜生产工单｜工序｜扫码｜追溯｜包装通光`
- MES系统（越南B部）：`越南B部｜B部MES｜MES B部｜越南B部MES`（长词优先于泛 MES）
- MES系统（越南C部）：`越南C部｜C部MES｜MES C部｜越南C部MES`（长词优先于泛 MES）
- 文件管理系统（国内）：`文件管理｜共享文件｜共享盘｜文档管理｜文件夹权限｜文件服务器`
- 电脑/打印机/网络问题：`电脑｜笔记本｜台式机｜开不了机｜无法开机｜不开机｜黑屏｜蓝屏｜死机｜卡顿｜打印机｜网络｜上不了网｜断网｜WiFi｜无线网`
- OA开发支持：`OA开发｜OA二开｜OA接口｜OA表单开发｜OA流程开发`
- ERP开发支持：`ERP开发｜金蝶开发｜ERP接口｜ERP二开`
- 北森招聘系统：`北森｜招聘系统｜招聘平台`
- 法大大电子签平台：`法大大｜电子签｜电子签名｜电子签章｜Fadada`
- 其他：不得仅因没有命中关键词而自动选择，必须由员工确认或人工处理。

`OA开发支持` / `ERP开发支持` 是**所属系统**，不是工单类型捷径。先定类型，再定系统。

## 实时匹配顺序

1. 用明确表述和类型关键词确定工单类型。故障 / 报错 / 无法 优先于需求词。
2. 用当前消息与**本张未完结工单**上下文匹配问题关键词（不含已取消、已提交、其它会话的旧单）。
3. 位置：员工在**本张工单**明确说明的故障地点 > 本条消息实际附带的已核验部门按 `REGION_MAPPING.md` 得到的区域。公开版通道没有部门时，不要假装已解析区域。历史工单、已取消单、已提交单里的地点不算。
4. 带地点的所属系统必须同时匹配地点。区域仅为「深圳」（未细分园区）时，**不得**自动改成（深汕）或（智园），必须请员工确认；也不要生成不存在的 `电脑/打印机/网络问题（深圳）`。
5. **无已核验部门且本张工单员工未说地点**：不得自动选择电脑/打印机/网络问题的地点项，也不得在「邮箱系统（国内） / 邮箱系统（越南）」「文件管理系统（国内） / 文件管理系统（越南）」之间默认国内项；用 `xA企微回复模板.md` 国内/越南短卡，不要套电脑园区 1–6。
6. **MES 越南 B部 / C部**：员工未明确说「越南B部 / B部」或「越南C部 / C部」时，不得在 `MES系统（越南B部）` 与 `MES系统（越南C部）` 之间默认任一项；用 MES B/C 短卡。明确说 B 部则选 `MES系统（越南B部）`；明确说 C 部则选 `MES系统（越南C部）`。
7. 电脑/打印机/网络问题在**本张工单已有地点**时：`智园` → `（智园）`，`大磡` / `深汕` / `光明` / `泗洪` / `越南` → 对应同名项。问地点时员工为本张工单回序号也算已说明：`1` 智园、`2` 大磡、`3` 深汕、`4` 越南、`5` 光明、`6` 泗洪（也认 `1.` / `1、智园`）。已取消/已提交后再报新问题，必须重新问，不得沿用上一张单的序号。
8. 只有唯一所属系统才能写入 `systemName` 并 `prepare`。建议责任人只能取自 `ROUTING_RULES.md` 同一系统行。

## 用户可见输出

匹配过程静默。唯一命中时不解释原因、不输出关键词。零条或多条时直接请员工确认 `区域` 和 `所属系统`；候选只能来自 `ROUTING_RULES.md` 当前类型清单。

## 验收样例

输入：已核验部门映射为 `越南/越南`，员工反馈“多台电脑无法开机”。

预期：工单类型 `运维支持`，所属系统 `电脑/打印机/网络问题（越南）`，建议责任人（仅处理人）`黄文明、阮世山、新文雄`。不解释匹配，不再问区域和系统。

反例：公开版通道无部门，员工只说“电脑开不了机”。不得自动选地点系统，必须请员工确认区域和所属系统。

反例：同一会话上一张单已选「1 智园」后取消或已提交，员工再发“电脑坏了”。不得沿用智园，必须重新问 1–6。
